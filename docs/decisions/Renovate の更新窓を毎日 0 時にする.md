# Renovate の更新窓を毎日 0 時にする

## 背景と課題

これまで Renovate の更新窓を月曜 0:00-4:59 にまとめていたが、次の 2 つの課題が出ていた。

- 1 週間分の更新 PR が月曜に集中し、変更内容や新機能を丁寧に追い切れなくなっていた
- 自動マージされた PR でも毎回 GitHub 通知が届き、月曜に大量の通知がノイズとして溜まっていた

日中の集中を妨げずに、1 回あたりの確認量を数件に抑えつつ、自動マージ済みの通知も自動で片付く運用へ切り替える必要がある。

```text
00:00-04:59  Renovate が更新 PR を作成・自動マージ
  ↓
08:00        日次レビューが変更解説・修正 PR・提案 issue を作成し、確認済みの自動マージ通知を Done にする
  ↓
朝           人間は 1 日分 (0〜数件) のレポートだけを確認する
```

## 検討した選択肢

### 更新ペース

| 選択肢 | 評価 |
| --- | --- |
| 週 1 まとめ (月曜 0:00-4:59) | 割り込みは週 1 回だが、1 回の量が多く確認が追いつかない |
| 毎日深夜 (0:00-4:59) | 1 日あたり 0〜数件に分散され、毎朝数分で確認できる。日中の割り込みも起きない |
| 常時 (schedule なし) | 開発中にも PR と通知が随時届き、集中を削ぎやすい |

### 自動マージ通知の抑止方法

| 選択肢 | 評価 |
| --- | --- |
| `automergeType: "branch"` に変える | PR を作らず通知を 0 件にできるが、全リポジトリの CI トリガー (`on.push.branches`) に `renovate/**` の追加と Ruleset の bypass 設定が必要 |
| `group:allNonMajor` で 1 PR にまとめる | 通知は 1 リポジトリあたり 1 件に減るが、1 パッケージの CI 失敗で他の更新もまとめて止まる |
| PR のまま維持し、日次レビュー完了後に通知を Done にする | 各リポジトリの CI・Ruleset を変えずに済み、変更解説と適用 PR の確認が終わった通知だけを自動で片付けられる |

## 決定

- `default.json` の `schedule` を `["* 0-4 * * *"]` (毎日 0:00-4:59 JST) に変更する
- `lockFileMaintenance.schedule` は週 1 回の火曜 0:00-4:59 JST を維持する
- `automergeType` は既定の `"pr"` のまま維持する
- 確認済みの自動マージ PR の通知は `nozomiishii/brain` 側の日次レビュー完了時に Done にする

## 結果

### 良くなったこと

- 1 回あたりの更新件数が 0〜数件に減り、新機能や非推奨の変更を毎朝無理なく追えるようになる
- 各リポジトリの CI 設定や Ruleset を変更せずに、自動マージ通知のノイズを消せる

### 引き受けたコスト

- 毎日 0:00-3:00 に開発している場合、その時間帯に自動マージが `main` へ入ることがある
- 確認完了前の早朝 (0:00-8:00) は自動マージ PR の通知が一時的に残る

### 保留した論点

- なし
